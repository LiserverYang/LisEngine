# LisEngine 的引擎架构

从我打算做这个引擎起，我就将目光放在了 Unity 和 Unreal 身上。我想要做的，就是使用 C++ 做一个简易的 Unity。因此，从这个项目文件夹被创立，我就打算做一个传统的 GameObject-Component 架构，而不是 ECS。

## 编译系统

按照开发的顺序，引擎可以说是从地基开始向上铺的，除了反射系统我本身很感兴趣以外，所有的开发顺序都是从底到深。我第一个所参考的就是虚幻引擎的编译系统，这个系统最大的特点就是将项目拆分成了模块，使得引擎变得解耦合并且可维护。我认为这是一个很好的起点，现在来看这个编译系统比我想象地还要稳定、搞笑，我现在可以将大部分精力放在开发引擎而不是编写编译脚本上。可能我这个项目的编译系统和 Unreal 相比有点歪，因为我没有接触过太多的 Unreal。但是目前来看我认为这个系统完全胜任工作。我将按照我的项目阐述编译系统。

首先我要介绍一些基础概念：

1. Target：编译的“目标”，可以认为是一个子项目，类似于 VS 中的 “解决方案”。
2. Module：每个 Target 下都会有若干个 Module “模块”，模块是项目的最小功能单位，一般将一个功能拆分为一个模块。

每个 Target 和 Module 都会有一个自己的 XXX.build.py 来配置这个 Target 或 Module 的细节。例如你可以选择将模块编译为静态库、动态库或者作为 Target 的入口点。可以查看 Templates 文件夹。

当 build.py 被运行后，编译系统会搜索所有的 Target ，随后根据 Target 的配置编译所有的 Module 。
